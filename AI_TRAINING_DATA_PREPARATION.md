# Инструкция: подготовка и загрузка архива из ~140 файлов для обучения/индексации AI

> Цель: безопасно и повторяемо превратить "хаотичный" архив документов (PDF/DOC/DOCX, любые имена) в структурированный набор, загрузить его в систему и синхронизировать с AI backend.

## 1) Что важно заранее

- Имена файлов **могут быть любыми** — это нормально.
- Для корректной автоматической обработки желательно, чтобы в имени присутствовал код стандарта (например `SHNQ 2.01.01-22`, `КМҚ 1.03.04-22`, `KR 01.01-23`).
- Если код в имени не найден, файл всё равно загрузится, но понадобится ручная проверка в админке.

## 2) Подготовка окружения

### Минимум
- Python 3.12+
- LibreOffice (для конвертации DOC/DOCX → PDF)
- Запущенный Flask backend
- (Опционально) запущенный Django AI backend для синхронизации

### Проверка LibreOffice
```bash
libreoffice --version
```

## 3) Рекомендуемый pipeline

### Шаг 1. Распаковать архив

Пример:
```bash
mkdir -p documents-archive
# распакуйте архив в documents-archive/source
```

### Шаг 2. Нормализовать файлы (обязательно)

Из корня репозитория:
```bash
python scripts/normalize_documents.py ./documents-archive/source ./documents-normalized
```

Результат:
- `documents-normalized/original/` — резервные копии исходников
- `documents-normalized/normalized/` — нормализованные PDF
- `documents-normalized/metadata.csv` — журнал обработки

### Шаг 3. Проверить `metadata.csv`

Критические проверки:
- `status = error` → файлы, которые не обработались
- `code` пустой/некорректный → переименовать вручную и прогнать снова
- `size_kb = 0` → повреждённый файл

### Шаг 4. Массовая загрузка в backend

```bash
python scripts/bulk_upload.py ./documents-normalized/normalized
```

Если AI backend пока не поднят:
```bash
python scripts/bulk_upload.py ./documents-normalized/normalized --no-ai
```

## 4) Как работать с файлами без логики в названиях

Если названия не содержат код стандарта (`scan1.pdf`, `doc_final_v3.docx`):

1. Добавьте префикс и код вручную в имя файла перед запуском нормализации, например:
   - `scan1.pdf` → `SHNQ 2.01.01-22 scan1.pdf`
2. Прогоните `normalize_documents.py` повторно.
3. Проверьте, что в `metadata.csv` у файла есть валидный `code`.

> Важно: если код не извлечён, система сохранит файл с безопасным именем, но качество поиска/привязки в AI будет ниже.

## 5) Стандарт качества перед импортом

Перед массовой загрузкой убедитесь:

- [ ] Все документы в `normalized/` имеют формат `.pdf`
- [ ] Не осталось записей `status=error` в `metadata.csv`
- [ ] Для каждого файла определён код стандарта
- [ ] Для каждого PDF открываются страницы (файл не битый)

## 6) После загрузки: проверка результата

1. В БД появились новые документы.
2. У документов рассчитано число страниц (`pages > 0`).
3. Цена выставлена по формуле `страницы × PRICE_PER_PAGE`.
4. При включённой синхронизации AI нет массовых ошибок callback/timeout.

## 7) Частые ошибки и быстрые решения

- **`LibreOffice not found`**
  - Установить LibreOffice и добавить в PATH.
- **Ошибка конвертации DOC/DOCX**
  - Открыть файл вручную в LibreOffice и сохранить как PDF.
- **Не распознался код стандарта**
  - Переименовать файл так, чтобы в имени был явный код (`SHNQ 1.02.10-23`).
- **AI backend недоступен**
  - Импортировать через `--no-ai`, затем сделать отложенную синхронизацию.

## 8) Рекомендуемый режим для вашего кейса (~140 файлов)

1. Нормализация всего архива одной командой.
2. Исправление всех `error` в `metadata.csv`.
3. Пробная загрузка 10–15 файлов.
4. Полная загрузка всех файлов.
5. Smoke-тест AI чата на 5–10 типовых вопросов.
