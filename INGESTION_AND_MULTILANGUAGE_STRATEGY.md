# Стратегия: архив, мультиязычные версии и обучение AI

> Цель: сделать предсказуемый процесс, при котором новые документы автоматически попадают в продажу и в AI-индексацию, а рус/узб/англ версии одного стандарта связаны как один продукт.

## 1) Где хранить архив и как обеспечить авто-подгрузку

## Рекомендуемая структура

Создайте единый каталог-источник (например, на NAS или mounted volume):

```text
/mnt/standards-archive/
  incoming/                 # сюда кладём новые файлы (как есть)
  processed/
    original/               # резерв оригиналов
    normalized/             # нормализованные PDF для публикации
    metadata.csv            # результаты нормализации
  failed/                   # файлы, которые не удалось разобрать
  manifests/
    batch_manifest.csv      # ручные соответствия и язык
```

### Почему так
- `incoming/` — рабочая «точка входа» для новых пакетов.
- `processed/normalized/` — готово для продажи и загрузки в backend.
- `manifests/` — контроль качества и явные связи между языковыми версиями.

## Поток обработки (рекомендуемый)

1. Оператор кладёт новые файлы в `incoming/`.
2. Запускается нормализация (`scripts/normalize_documents.py`).
3. Проверяется `metadata.csv` + `batch_manifest.csv`.
4. Выполняется загрузка (`scripts/bulk_upload.py`).
5. Для каждого документа выполняется sync в AI backend.
6. Обработанные файлы перемещаются в `processed/original/`, ошибки — в `failed/`.

> На данном этапе авто-режим лучше сделать через cron/systemd timer (например, каждые 10–30 минут), но с обязательным логом и dry-run режимом перед боем.

## 2) Нейминг и связывание RU/UZ/EN версий

### Бизнес-модель
Покупатель видит **один товар (стандарт)**, внутри которого есть языковые версии:
- `ru`
- `uz`
- `en`

### Базовый ключ связи
Используйте единый `standard_code` как ключ (например, `SHNQ 2.01.01-22`).

### Рекомендуемый шаблон имени файла

```text
<STANDARD_CODE>__<LANG>__v<REV>.pdf
```

Примеры:
- `SHNQ_2.01.01-22__ru__v1.pdf`
- `SHNQ_2.01.01-22__uz__v1.pdf`
- `SHNQ_2.01.01-22__en__v1.pdf`

### Если входные имена хаотичные
Используйте `batch_manifest.csv`, где явно задаётся связь:

```csv
source_filename,standard_code,language,title,revision,is_active
scan_001.pdf,SHNQ 2.01.01-22,ru,SHNQ 2.01.01-22,1,true
scan_002.pdf,SHNQ 2.01.01-22,uz,SHNQ 2.01.01-22,1,true
scan_003.pdf,SHNQ 2.01.01-22,en,SHNQ 2.01.01-22,1,true
```

## Что нужно добавить в модель данных (next step)

Сейчас `Document` не разделяет языковые версии как один товар. Для корректной продажи по языкам добавьте:

1. `standard_code` (строка, индекс)
2. `language` (`ru|uz|en`)
3. `variant_group_id` или связь на `StandardProduct`
4. уникальность: `(standard_code, language, revision)`

После этого UI на карточке документа может показывать переключатель языка для одного стандарта.

## 3) Как сделать обучение и протестировать уже сейчас

## Минимальный рабочий сценарий (сегодня)

1. Положить архив в `incoming/`.
2. Прогнать нормализацию:

```bash
python scripts/normalize_documents.py /mnt/standards-archive/incoming /mnt/standards-archive/processed
```

3. Проверить `metadata.csv` и исправить ошибки.
4. Загрузить в backend:

```bash
python scripts/bulk_upload.py /mnt/standards-archive/processed/normalized
```

или без AI:

```bash
python scripts/bulk_upload.py /mnt/standards-archive/processed/normalized --no-ai
```

5. Проверить UI:
- `/documents`
- `/documents/:id`
- AI виджет на главной

6. Проверить AI вручную 10–20 вопросами:
- общий вопрос по документу;
- вопрос по конкретному пункту;
- вопрос по таблице.

## Acceptance-критерии для теста AI

- Не менее 80% ответов содержат релевантный источник.
- Нет "галлюцинаций" по отсутствующим стандартам.
- Для таблиц/изображений ответ не ломает разметку.
- Среднее время ответа приемлемо (например, < 12 сек в локальной сети).

## Риски и как снизить

1. **Смешение языков одного стандарта**
   - Решение: `standard_code + language + manifest` как строгий контракт.

2. **Плохие имена файлов**
   - Решение: обязательный `batch_manifest.csv` для каждой новой партии.

3. **Нестабильные ответы AI**
   - Решение: контрольный набор вопросов + baseline + логирование источников.
